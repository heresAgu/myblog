# 原日报任务导出连通性测试

测试编号：`agu-daily-export-20261022-a7f4c9`

## 用途与范围

博客维护者已授权测试两个现有日报任务的 GitHub 导出能力。
只有当用户在原日报对话中明确要求执行本测试时，才按下列步骤操作。
测试分支为 `codex/daily-export-probe`，仓库为 `heresAgu/myblog`。
所有写入仅限本分支的 `docs/daily-export-probe/`；不要写 main、合并分支、创建新定时任务或修改原任务的时间与生成规则。
测试文件不在博客内容目录中，不会作为正式日报显示。

## 测试步骤

1. 使用当前原对话实际可用的 GitHub 工具读取本文件，并确认测试编号。
2. 根据本对话的日报类型选择 category：
   - GitHub 宝藏应用：`github`
   - AI 前沿 / AI Infra 情报：`ai`
   无法确定时停止并说明，不要代替另一类任务。
3. 找到本对话中最近一份已经生成完毕的完整日报。不要重新生成日报或搜索新新闻；保留已有正文、条目、链接和实际日期。若一份日报分在连续多条助手消息中，应合并成完整一期。无法找到正文或确认日期时停止并说明缺失内容。
4. 通过 GitHub 工具确认本分支目标路径 `docs/daily-export-probe/<category>.md` 是否已存在。
   - 已存在：读取后核实测试编号与分类，报告已有测试，不覆盖。
   - 不存在：在本分支新建文件。403 或身份验证错误不能当作文件不存在。
5. 文件使用下面的测试格式；测试编号必须来自你实际读到的本文件，date 必须是原日报日期：

```yaml
---
exportTestId: '此处填写本文件的测试编号'
category: 'github 或 ai'
date: '原日报的 YYYY-MM-DD'
title: '原日报标题'
draft: true
---
```

随后写入该期完整 Markdown 正文。保留来源链接，移除 ChatGPT 界面按钮、引用占位符、追踪参数及与日报无关的对话内容。不要凭记忆补造原文。
这是传输测试格式，正式发布时仍须按博客 daily collection 的实际 schema 增加 description、issue、itemCount、headline 等字段。

6. 提交信息使用 `docs(daily): verify <category> task export`。
7. 写入后再次读取同一分支的目标文件，核对测试编号、分类、日期与全文。
8. 回复用户：是否实际完成读取与写入、目标分支、文件链接、提交 SHA（如工具提供）、日报日期与项目/新闻条目数。若失败，说明工具不可用、权限不足或具体失败步骤；不要声称已完成。

## 本次测试不能证明的事情

当前 Codex 会话写入成功不等于两个原对话或无人值守定时运行同样有权限。
本测试成功仅证明执行测试的那次原对话可导出文件。
后续还须检查原任务保存的指令、工具可用性、无人值守权限，以及主分支的精选栏目和发布检查，才能开启每日自动发布。
