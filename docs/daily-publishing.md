# 每日精选内容格式

入口为 `/curated`，分为 GitHub 宝藏（`github`）与 AI 前沿情报（`ai`）。
首页每类仅展示最新一期；归档按日期排列，每页最多七天。详情页保留整期正文。

## 添加一期日报

两类任务各写各的文件，避免互相覆盖：

- `src/content/daily/github/YYYY-MM-DD.md`
- `src/content/daily/ai/YYYY-MM-DD.md`

先生成草稿，核对后再发布。`draft` 默认为 `true`，草稿不会出现在首页、归档、搜索或详情路由。
GitHub 宝藏与 AI 情报各自连续编号；使用内容实际发布的日期，不使用导入日期。

```yaml
---
title: 'GitHub 宝藏应用 · 第 3 期'
description: '用一两句话概括本期内容。'
date: 2026-10-22
category: github
issue: 3
itemCount: 5
headline: '首页展示的一条主推标题'
tags: ['github', '开源应用']
draft: true
---
```

如有公开的原始日报，可额外提供 `source: 'https://...'`。
`itemCount` 应与正文里的推荐项目或新闻条目数一致，`headline` 用于首页的单行预告。

GitHub 日报先放速览表，再按二级标题介绍每个应用。保留仓库链接、适用平台、功能、使用门槛与推荐理由。
Stars 标注查询日期；历史快照不可写成实时排行。

AI 日报先放三条重点，再用二级标题划分栏目、三级标题列出新闻。每条新闻给出原始出处，区分事件发生日期和报道日期。
无法核实的内容留在草稿中，不为凑数增加新闻。

## 发布检查

1. 检查出处、日期、推荐数量和正文排版，将 `draft` 改为 `false`。
2. 运行 `bun run build:checked`，本地预览首页窄栏、分类归档和详情页。
3. 按博客现有的 GitHub → Vercel 流程发布。

## 与定时任务衔接

当前已提供内容格式与展示入口，未更改 ChatGPT 中现有定时任务。
可让任务先按上述格式输出 Markdown，再导入对应文件。
若以后让任务直接操作仓库，应限定为新增当期、对应分类的草稿；不要覆盖旧期内容或顺带提交其他未完成的改动。
站点不会抓取私人聊天，也不会仅凭分享链接自动获得后续日报。
